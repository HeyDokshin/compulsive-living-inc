# 01 · Технологический стек

## Выбор 3D-движка

| Кандидат | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **Three.js** | Самая большая экосистема и сообщество, полный контроль над рендером, лёгкий, идеально для воксельного мешинга (BufferGeometry, InstancedMesh), WebGPU-рендерер | Это рендерер, а не движок: цикл, ECS, ввод, сохранения пишем сами | ✅ **Выбран** |
| Babylon.js | Полноценный движок, встроенный инспектор, физика, GUI | Тяжелее, свои абстракции мешают кастомному воксельному пайплайну | Запасной вариант |
| PlayCanvas | Хороший редактор | Редактор облачный, движок привязан к их инструментам | Нет |
| Godot (экспорт в Web) | Мощный редактор | Это не JavaScript, тяжёлый web-билд | Нет |

**Почему Three.js:** игра почти целиком состоит из своей логики (воксели, сетка, NPC, время, экономика). Готовый «движок» дал бы мало, а ограничений добавил бы много. Three.js рисует, всё остальное — наша собственная расширяемая архитектура, где мы контролируем каждую точку расширения.

## Полный стек

| Слой | Технология | Зачем |
|---|---|---|
| Язык | **TypeScript** (strict) | Типизированные реестры и API плагинов: мод получает автодополнение |
| Сборка / dev | **Vite** | Мгновенный HMR, горячая перезагрузка контента и плагинов |
| Рендер | **three** | Ортографическая изометрическая камера, воксельные чанки |
| ECS | **miniplex** | Объектный, типизированный ECS: компоненты — обычные объекты, легко сериализовать и расширять |
| Валидация данных | **zod** | Схемы для конфигов, контента, сохранений; понятные ошибки в модах |
| Формат контента | **JSON5** (+ TS для логики) | Данные редактируются без программирования, с комментариями |
| UI (HUD, инвентарь, диалоги) | **Preact + @preact/signals** поверх canvas | Лёгкий, реактивный, удобно привязывать к состоянию игры |
| Отладочная панель | **Tweakpane** | Живая настройка любых параметров (время, погода, скорость, освещение) |
| Звук | **Howler.js** | Музыка по времени суток, SFX, позиционный звук |
| Сохранения | **IndexedDB** через **idb** | Большие миры, несколько слотов, версионирование |
| Тяжёлые вычисления | **Web Workers** (+ **comlink**) | Генерация мира и мешинг чанков вне главного потока |
| Шум для генерации | **simplex-noise** | Рельеф острова, распределение ресурсов |
| Модели | **MagicaVoxel `.vox`** → свой загрузчик | Мебель, персонажи, предметы в едином воксельном стиле |
| Тесты | **Vitest** | Логика систем (экономика, время, рецепты) без рендера |
| Линт / формат | **ESLint + Prettier** | |
| Десктоп/мобильная сборка (позже) | **Tauri** / **Capacitor** | Опционально, когда игра будет готова |

## Принципиальные решения

1. **Без физического движка.** Нужны только AABB-коллизии с вокселями и сеткой — пишем сами (~200 строк). Rapier подключаем позже, если появятся физические игрушки.
2. **Фиксированный шаг симуляции** (например, 20 тиков/с) + интерполированный рендер. Детерминизм упрощает сохранения и возможный мультиплеер.
3. **Логика не зависит от рендера.** Системы симуляции можно запускать в тестах и в воркере без three.js.
