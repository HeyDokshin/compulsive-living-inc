# 02 · Архитектура: всё — плагин

Главный принцип: **ядро игры само является набором плагинов**. Ловля рыбы, магазин, жители, погода — это плагины, использующие тот же публичный API, что и будущие моды. Если что-то можно сделать в базовой игре, это можно сделать и модом.

## Слои

```
┌───────────────────────────────────────────────────────────┐
│  content/  — пакеты данных (JSON5 + .vox + звуки)         │  ← дизайнер
├───────────────────────────────────────────────────────────┤
│  plugins/  — механики: core, fishing, villagers, shop ... │  ← геймплей
├───────────────────────────────────────────────────────────┤
│  sdk/      — публичный API для плагинов (стабильный)      │  ← контракт
├───────────────────────────────────────────────────────────┤
│  engine/   — цикл, ECS, реестры, события, мир, рендер,    │  ← фундамент
│              ввод, UI-хост, сохранения, время, отладка    │
└───────────────────────────────────────────────────────────┘
```

Правило зависимостей: стрелки только вниз. `engine` ничего не знает про рыбу; `plugins` не импортируют внутренности `engine`, только `sdk`.

## Движок: кто за что отвечает

| Модуль | Ответственность |
|---|---|
| `Game.ts` | корень композиции: создаёт сервисы и связывает их, загрузка, горячая перезагрузка, очередь задач (`serial`) |
| `plugins/createPluginApi.ts` | API одного плагина и автоматическая очистка всего, что он зарегистрировал |
| `plugins/ServiceRegistry.ts` | сервисы, которые плагины дают друг другу |
| `session/SessionManager.ts` | новая игра и загрузка (перезапуск сессии), сохранение, автосохранение, проверка импорта, при битом сейве — титульный экран, сам сейв остаётся нетронутым |
| `mods/ModManager.ts` | моды: папка и установленные, включение, код через blob-модули, контент и конфиги, правка и экспорт; `zip.ts`, `package.ts`, `code.ts` — чистые части |
| `session/Title.ts` | титульный экран: фон-остров, облёт камеры, продолжить / новый / острова / настройки; пока он открыт, HUD скрыт, ввод и сохранение стоят |
| `session/settings.ts` | настройки игрока на этом устройстве (качество, звук, FPS), пресеты качества |
| `render/Renderer.ts` | сцена, свет, пост-обработка, чанки, пикинг под мышью |
| `render/CameraController.ts` | слежение за игроком, свободная камера, зум и поворот |
| `world/WorldService.ts` | генерация, правка блоков, кэш «твёрдости» по номеру палитры |
| `world/Interiors.ts` | помещения: углы мира под комнаты (всегда открытое море), кто внутри, что рисовать, сохранение |
| `world/Blockers.ts` | индекс сущностей-препятствий (компонент `blocker`, размер в клетках): по нему движок отвечает на `movement:blocked` и находит большие сущности для взаимодействия |

## Структура репозитория

```
src/
  engine/
    loop/          фиксированный шаг, фазы систем
    ecs/           обёртка над miniplex, схемы компонентов
    registry/      универсальный Registry<T> с namespaced id
    events/        шина событий + перехватываемые хуки
    world/         чанки, блоки, генерация, мешинг (worker)
    render/        three.js сцена, изо-камера, освещение, атлас
    input/         действия → привязки клавиш/геймпада/тача
    ui/            Preact-хост, слоты для UI плагинов
    time/          игровые часы, календарь, сезоны
    save/          IndexedDB, версии, миграции
    debug/         Tweakpane, консоль команд, оверлеи
    plugins/       загрузчик, граф зависимостей, HMR
  sdk/             index.ts — то, что видит плагин
  plugins/
    core/          игрок, инвентарь, предметы, взаимодействие
    nature/        деревья, цветы, камни, раскопки
    fishing/  bugs/  museum/  shop/  crafting/
    housing/  villagers/  weather/  quests/  events/
content/
  core/            blocks.json5, items.json5, recipes.json5 ...
  <pack-id>/       любой пакет контента
config/            game.json5, balance.json5, debug.json5
```

## 1. Реестры (Registry)

Любая сущность контента — запись в реестре с id вида `namespace:name`.

```ts
api.registries.blocks.register({ id: 'core:grass', texture: { top: 'grass_top', side: 'grass_side' }, diggable: true })
api.registries.items.register({ id: 'fishing:sea_bass', category: 'fish', sellPrice: 400, icon: 'sea_bass' })
api.registries.items.modify('core:apple', item => ({ ...item, sellPrice: 150 }))   // моды могут патчить
```

Стандартные реестры: `blocks`, `items`, `entities` (префабы), `recipes`, `tools`, `interactions`, `npcs`, `personalities`, `dialogues`, `species` (рыба/жуки/…), `furniture`, `biomes`, `weathers`, `events`, `quests`, `shops`, `sounds`, `commands`, `settings`.
Плагин может **создать свой реестр** — `api.registries.create<T>('fishing:baits', schema)` — и другие плагины смогут в него добавлять.

Каждая запись валидируется zod-схемой при регистрации. JSON5-файлы из `content/` загружаются в те же реестры автоматически.

## 2. Сущности: ECS + префабы

- **Компоненты** — простые сериализуемые объекты: `position`, `velocity`, `model`, `inventory`, `growable`, `shakeable`, `npc`, `schedule`, `furniture`, `collider`…
- Плагин регистрирует новые компоненты со схемой: `api.components.define('fishing:fishShadow', schema)` — схема нужна для сохранения и отладочного инспектора.
- **Префаб** = именованный набор компонентов в данных:

```json5
// content/core/entities.json5
{ id: 'core:apple_tree', components: {
    model: { vox: 'trees/apple' },
    collider: { size: [1, 3, 1] },
    shakeable: { drops: 'core:apple', count: 3, regrowDays: 3 },
    choppable: { tool: 'core:axe', hits: 3, drops: { 'core:wood': [1, 3] } },
}}
```

- **Системы** регистрируются в фазах с приоритетом:
  `input → preUpdate → update → postUpdate → render` (+ `daily`, `hourly` по игровым часам).

```ts
api.systems.add({ id: 'nature:regrow', phase: 'daily', run: (world, ctx) => { ... } })
```

## 3. События и хуки

Два механизма:

| | События (`events`) | Хуки (`hooks`) |
|---|---|---|
| Назначение | «что-то случилось» | «что-то вот-вот случится» — можно изменить или отменить |
| Пример | `item:picked`, `day:started`, `npc:moved_in` | `item:beforeSell` (изменить цену), `player:beforeInteract` (отменить) |
| API | `api.events.on('fish:caught', e => ...)` | `api.hooks.tap('shop:price', (price, ctx) => price * 1.1, { priority: 10 })` |

Все события типизированы: плагин объявляет их через `declare module '@sdk' { interface Events { ... } }` — автодополнение у всех потребителей.

## 4. Взаимодействия (Interaction matrix)

Сердце «песочницы». Каждое действие — правило «инструмент × цель → эффект», а не `if` в коде игрока:

```ts
api.registries.interactions.register({
  id: 'nature:dig_hole',
  tool: 'core:shovel',            // или tag: '#core:shovels'
  target: { block: '#core:diggable' },
  condition: ctx => !ctx.tileHasEntity,
  run: ctx => ctx.world.setBlock(ctx.pos, 'core:hole'),
  anim: 'dig', sound: 'core:dig',
})
```

Добавить новую механику (например, «полить цветок лейкой») = зарегистрировать одно взаимодействие. Приоритеты разрешают конфликты, хук `interaction:resolve` позволяет модам переопределять.

### Сервисы

Плагины могут давать друг другу API: `api.services.provide('items:inventory', impl)` и `api.services.get('items:inventory')` у зависимого плагина (тип описывается через `declare module '@sdk' { interface Services { ... } }`). Как и всё остальное, сервис снимается при выгрузке плагина.

## 5. Теги

Как в Minecraft: `#core:fruits`, `#core:diggable`, `#core:furniture/wall`. Рецепты, взаимодействия, магазины и квесты ссылаются на теги, а не на конкретные id — новый контент из мода автоматически включается в существующие механики.

## 6. Мир

- Один остров ограниченного размера: мир 128×128 клеток, высота 32, разбит на **чанки 16×16×32**. Форма процедурная, площадь суши постоянная, суша всегда одним куском.
- **Уровни** (`config/world.json5`: `ground`, `levels`; в API — `api.world.ground`, `levels`, `topY`): уровень 1 — земля, море вровень с ней (просто не покрывает сушу). Природный рельеф — максимум два уровня, перепад не больше блока. Всего 5 уровней: блоки ставятся не выше 4 над землёй, 5-й — технический, для вещей сверху. Дома, лавка, музей и ящик продажи генерируются только на уровне земли.
- Блоки хранятся в `Uint16Array` + палитра id из реестра (сохранения не ломаются при добавлении модов).
- **Слои**: `terrain` (воксели) + `objects` (сущности на сетке: деревья, мебель, предметы на земле). Одна клетка = 1 блок.
- Генерация — **конвейер шагов** в реестре `worldgen` (`order` задаёт порядок): сейчас `shape → rivers → ponds → surface → voxels` из плагина `terrain`, дальше `resources → structures → npc_houses`. Мод может вставить шаг, заменить или выключить любой.
- Мешинг (greedy meshing + ambient occlusion по вершинам) — в пуле Web Worker'ов. Генерация — в главном потоке, потому что её шаги являются функциями плагинов (остров 128×128 строится за ~20 мс).

## 7. Рендер и камера

- `OrthographicCamera`, классический изометрический угол (наклон ~35°, поворот 45°), **поворот камеры шагами по 90°**, зум колёсиком.
- Один текстурный атлас, собираемый из реестра блоков при старте (моды добавляют текстуры — атлас пересобирается).
- Освещение — направленный «солнечный» свет, цвет и угол берутся из кривых времени суток (настраиваются в `config`).
- Пост-эффекты (опционально): tilt-shift, мягкие тени, outline под курсором.
- Скрытие стен/крыш, загораживающих игрока (cut-away), — важно для изометрии.
- **Стиль** (секция `style` в `config/engine.json5`, папка в панели F2): тонмаппинг Neutral, мягкие PCF-тени с ослабленной силой (тени цветные за счёт неба), пост-обработка `PostFX` (tilt-shift → цветокоррекция с подъёмом чёрного, теплом и виньеткой → вывод), изгиб мира в вершинном шейдере.
- `stylize(material)` — единая точка «внешнего вида»: изгиб мира, покачивание (растения), бегущие UV (вода). Любой материал плагина получает его через `api.render.stylize`. Тени считаются по неизогнутому миру, поэтому они остаются на своих поверхностях.
- При включённом изгибе мешер не склеивает грани больше 1 блока: иначе вершины длинных граней не совпадают с соседними и появляются щели.
- **Смешанный стиль и детализация по зуму.** Издалека мир — мягкий пиксель-арт, вблизи отдельные черты становятся «настоящими»: всё, что зависит от зума, считает `Renderer.pixelsPerBlock` (экранных пикселей на блок) и меняется плавно.
  - *Процедурные материалы* (`engine/materials`, реестр `materials`): стопка слоёв из бесшовных узоров (`noise`, `ridged`, `cells`, `cracks`, `strata`, `wood`, `boards`, `grain`, `fibers`, `knit`, `pebbles`) с цветовыми рампами, режимами смешивания, масками и запечённым рельефом. Рисуются в воркере в любом размере; октавы мельче текселя затухают, поэтому 32 и 512 пикселей выглядят одинаково, только детальнее.
  - *Детализация блоков* (`AtlasDetail`): у атласа 16 текселей на блок; при приближении строится атлас 32…256, где текстуры с `material` показывают материал, остальные — тот же пиксель-арт. Новый уровень плавно проявляется поверх старого; уровни кэшируются (`render.detail`).
  - *Круглые персонажи* (`round` у рига, `smoothMesh.ts`): части рига мешатся как гладкие поверхности (surface nets по размытой мелкой копии вокселей), цвета вокселей сохраняются.
  - *Мех и волосы* (`fur` у модели): оболочки-инстансы поверх поверхности, пряди из 3D-узора, свисают под тяжестью, покачиваются, темнее у корней; число оболочек и длина растут с зумом (`render.characters`).
  - *Ткань* (`fabric` у модели, `render/fabric.ts`): материалы как светотень плетения поверх цвета палитры, проецируются с трёх сторон без UV, размер текстуры следует за зумом.
  - *Нарисованные лица* (`face` у модели): 2D-картинка проецируется на перёд круглой головы; рисует плагин `faces` на canvas размером под зум, только когда что-то поменялось.
- **Кадры камеры** (`IsoCamera.shot` + `cut(on, seconds)`): точка, зум, наклон, поворот и срез переднего плана плавно накладываются на обычный вид — для катсцен (плагин `cutscene`).

## 8. Время

- `TimeService`: реальные часы устройства (как в жанре) **или** ускоренное время — переключается в конфиге.
- Смещение времени и множитель доступны в отладочной панели («путешествие во времени» для тестов).
- События `minute`, `hour:changed`, `day:started`, `season:changed`; фаза систем `daily` догоняет пропущенные дни при загрузке (`catchUp(days)`).
- Календарь, сезоны, полушарие — данные.

## 9. UI

- Preact-хост поверх canvas. Плагины регистрируют UI в **слотах**: `screen` (весь экран под остальным HUD — полосы, оверлеи), `hud.topLeft`, `hud.topRight`, `hud.bottom`, `hud.bottomLeft`, `hud.bottomRight`, `hud.center`. `api.ui.cinema` — режим сцены: HUD уходит, окна и `screen` остаются.
- Состояние для UI — через signals, которые плагины выставляют (`api.ui.state`).
- Общие UI-примитивы в SDK: окно, сетка инвентаря, диалоговое облачко, радиальное меню инструментов, тосты.

## 10. Сохранения

- `SaveData` = формат + метаданные + **мир** (все чанки RLE + палитра id) + **сущности** (постоянные компоненты) + **данные плагинов** (`{ version, data }`).
- Мир хранится целиком, а не диффом от генерации: сейв переживает изменения генератора и модов. Номера блоков переназначаются через их id.
- Загрузка — это перезапуск сессии: выгрузить плагины → очистить сущности → загрузить плагины → сгенерировать мир (плагины получают свои данные генерации) → наложить сохранённые воксели → восстановить сущности → `load()` плагинов → `start()`.
- Данные отсутствующих плагинов и неизвестные компоненты сохраняются как есть и возвращаются, когда мод снова установлен.
- Хранилище — `SaveStorage` (IndexedDB в браузере, в памяти в тестах). Слоты, автосохранение, экспорт и импорт JSON.

## 11. Плагины

```ts
// src/plugins/fishing/index.ts
import { definePlugin } from '@sdk'

export default definePlugin({
  id: 'fishing',
  version: '0.1.0',
  dependsOn: ['core', 'nature'],
  config: FishingConfigSchema,          // попадёт в config и Tweakpane автоматически
  setup(api) {
    api.registries.items.register(...)
    api.registries.interactions.register(...)
    api.systems.add(...)
    api.ui.slot('hud.bottom', FishingMeter)
    api.commands.register('fish', ...)   // /fish spawn sea_bass
  },
})
```

- Загрузчик строит граф зависимостей, вызывает `setup` по порядку, затем `start`.
- **HMR**: при правке плагина в dev он выгружается (`dispose`) и загружается заново без перезапуска мира.
- Внешние моды (`engine/mods`): папка `mods/` или `.zip` из главного меню; тот же API — см. [06-modding.md](06-modding.md).

## 12. Настройка и отладка («максимально удобно»)

- **Все числа баланса — в `config/*.json5`** со схемами; ни одной «магической константы» в коде систем.
- **Tweakpane**: каждая схема конфигурации автоматически превращается в панель с ползунками. Изменения применяются вживую и могут быть сохранены в файл.
- **Консоль команд** (клавиша `~`): `/give core:apple 10`, `/time set 18:30`, `/weather rain`, `/spawn villagers:any`, `/tp 40 40`, `/day skip 3`. Плагины регистрируют свои команды.
- **Инспектор сущностей**: клик по объекту → все компоненты, редактируемые на лету.
- **Оверлеи**: сетка, коллайдеры, границы чанков, пути NPC, зоны спавна рыб/жуков.
- **Горячая перезагрузка контента**: правка `items.json5` → предмет обновился в игре.
